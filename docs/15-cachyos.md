# 15. Производительность против CachyOS: честное сравнение

> Вопрос, с которого начинался проект: «защищённая система, которая не уступает CachyOS».
> Эта глава отвечает на него без рекламы: что CachyOS делает для скорости, что из этого
> есть или повторено здесь, что невозможно в рамках правил проекта и сколько стоит
> защита. В конце — как сравнить обе системы на **вашем** ноутбуке одним скриптом.

## 1. Откуда у CachyOS скорость

CachyOS — Arch с собственными репозиториями и ядром. Источники выигрыша:

| Что | Суть | Порядок выигрыша |
|---|---|---|
| Пакеты под x86-64-v3/v4 | весь userspace собран с AVX2 (v3) или AVX-512 (v4), часть — с `-O3`, LTO, PGO | в среднем единицы процентов; заметно — в коде без своей диспетчеризации по CPU (большинство быстрых библиотек — glibc, zstd, ffmpeg, mesa, Firefox — сами выбирают AVX2 при запуске) |
| Ядро linux-cachyos | планировщик BORE поверх EEVDF, Clang + ThinLTO + AutoFDO/Propeller, `-O3`, HZ=1000, preempt=full, свои патчи | отзывчивость под нагрузкой (игры, сборка в фоне); пропускная способность — единицы процентов |
| sched_ext (scx) | планировщики на BPF, переключаемые на лету | в отдельных нагрузках; это root-код в ядре |
| Настройки (cachyos-settings) | sysctl памяти и записи, zram, THP, планировщики ввода-вывода, ananicy-cpp (авто-nice) | плавность под давлением памяти и записи |
| Удобство | готовые профили питания, драйвер NVIDIA | — |

И то, что CachyOS делает **ценой защиты** (по умолчанию в cachyos-settings):
`kernel.sysrq=1`, непривилегированные user namespaces для всех,
`kernel.nmi_watchdog=0`, у NVIDIA — отключено обнуление памяти
(`NVreg_InitializeSystemMemoryAllocations=0`). Здесь всё это запрещено.

## 2. Что здесь то же самое или лучше

Сверено с ядром Void 6.18 (`/proc/config.gz`) и настройками CachyOS.

| Область | CachyOS | void-hardened | Итог |
|---|---|---|---|
| Частота таймера | HZ=1000 | HZ=1000 (ядро Void) | = |
| Вытеснение в ядре | preempt=full | `preempt=full` в cmdline (ядро Void — `PREEMPT_DYNAMIC`; режима `lazy` в нём нет) | = |
| Планировщик | BORE + EEVDF | EEVDF (mainline) + `sched_autogroup` | BORE лучше держит отклик при тяжёлой фоновой нагрузке; разница видна в играх, меньше — в браузере и терминале |
| Вытеснение памяти | MGLRU | MGLRU включён в ядре Void | = |
| swap | zram zstd, размер = RAM, swappiness 150 | zram zstd, 50 % RAM (`VH_ZRAM_PERCENT`), swappiness 180, `page-cluster=0` | ≈ |
| sysctl памяти | `vfs_cache_pressure=50`, `dirty_bytes=256M`, `dirty_background_bytes=64M` | то же самое (`50-vh-performance.conf`) | = |
| THP | `madvise` + `defrag=defer+madvise` | то же (`07-vh-mm.sh`) | = |
| TCP | BBR (v3 в их ядре) | BBR (v1, mainline) + fq | ≈ |
| Частота CPU | power-profiles-daemon | EPP по питанию одной записью в sysfs, без демона | = по скорости, на один демон меньше |
| Init и сервисы | systemd, десятки юнитов | runit, ~13 сервисов | **быстрее загрузка, меньше RAM** |
| Рабочий стол | KDE/GNOME/Hyprland… | mango + netline (Zig без libc, 0 пробуждений в простое) | **меньше RAM и пробуждений** |
| Графика | Mesa свежая | Mesa свежая (Void current) | = |
| Видео | VA-API | VA-API (iHD) в доверенном профиле браузера | = |

Где void-hardened выигрывает за счёт минимализма: время от ввода пароля LUKS до
рабочего стола, свободная RAM после входа, число процессов и пробуждений CPU в простое
(батарея), объём установки (около 1,4 ГБ с браузером). Цифры для вашего ноутбука даст
`tools/vh-bench` (раздел 5).

## 3. Чего не повторить в рамках правил проекта

Правило «только официальные пакеты Void, без сборки из исходников» (модуль 0 промпта)
исключает:

- **пакеты под x86-64-v3** — в Void их нет, а пересборка запрещена;
- **ядро с BORE, LTO, AutoFDO** — ядро только штатное (`linux6.18`);
- **sched_ext** — в ядре Void не собран (`CONFIG_SCHED_CLASS_EXT` не задан), и это
  правильно: BPF-планировщик — root-код в ядре;
- **ananicy-cpp** — нет в репозитории; его работу частично делает `sched_autogroup`
  (терминал с тяжёлой задачей — отдельная группа планирования) и ручной `nice`/`ionice`
  для фоновых задач;
- **проприетарный драйвер NVIDIA** — DKMS и неподписанный модуль несовместимы с lockdown
  (глава 04). Для этого ноутбука это не потеря скорости рабочего стола: mango и браузер
  работают на iGPU, а GTX 1650 обесточена — CPU получает больше теплового запаса на турбо.

Вывод: в синтетике на CPU (сжатие, компиляция, JS) CachyOS будет быстрее **на единицы
процентов** за счёт сборки под v3/LTO и **ещё на единицы процентов** — за счёт того, что
здесь включены меры защиты с ценой (следующий раздел). В отклике интерфейса, загрузке,
памяти и батарее эта система не уступает, а по большинству пунктов — легче.

## 4. Цена защиты — и что можно отключить без потери безопасности

| Мера | Цена | Решение |
|---|---|---|
| `init_on_free=1` | обнуление каждой освобождаемой страницы: ~1–5 % в задачах, активно выделяющих память (сборка, распаковка, браузер) | оставить: без неё открытый текст остаётся в свободной RAM (атака холодной загрузки) |
| `iommu.strict=1` | сброс IOTLB при каждом освобождении буфера DMA: заметно на NVMe с высоким IOPS (4K QD32), почти незаметно в обычной работе | оставить; замер — глава 11 |
| смягчения CPU (`mitigations=auto`) | как у CachyOS — там они тоже включены | = |
| AppArmor, seccomp, bwrap у браузера | доли процента | оставить |
| фильтр Wayland `vh-wlfilter` | лишний переход сообщений Wayland браузера через процесс на Python (данные кадров — через общую память, не копируются) | оставить; замер — загрузка CPU прокси при видео |
| одноразовый профиль браузера без JIT и GPU | JS в разы медленнее | только для недоверенных сайтов; обычная работа — в доверенном профиле с JIT и GPU |
| нет suspend | старт с выключенного ~20–40 с вместо мгновенного | цена удобства, не скорости (ключ LUKS в RAM при suspend) |

**Запрещённые «ускорения»** (выигрыш есть, но открывают атаки) — глава 11, раздел 8.
Отдельно о популярных для игровых ноутбуков:

- **андервольт** (`intel-undervolt` есть в репозитории) — пишет в MSR процессора; при
  `lockdown=confidentiality` запись в MSR из userspace запрещена. Снимать lockdown ради
  андервольта нельзя. К тому же на Comet Lake прошивки MSI обычно блокируют его сами
  (защита от Plundervolt).
- **`nowatchdog`, `kernel.nmi_watchdog=0`** — выигрыш — один свободный счётчик PMU и
  доли процента батареи; ломает перезагрузку при зависании (ключ остаётся в RAM).
- **`mitigations=off`** — 2–15 % в системных вызовах и AVX ценой чтения памяти ядра и
  чужих процессов из JS.

## 5. Как сравнить на своём ноутбуке

`tools/vh-bench` — один скрипт на POSIX sh, без зависимостей, кроме `zstd` и
`python3` (оба есть и в Void, и в CachyOS):

```sh
sh tools/vh-bench               # отчёт в ./vh-bench-<хост>-<дата>.txt
sh tools/vh-bench --fio         # плюс накопитель (нужен fio; файл 2 ГБ в $HOME, удаляется)
```

Что измеряет: время загрузки по `dmesg` и `/proc/uptime`, занятую RAM и число
процессов в простое, пробуждения CPU за 30 с простоя (`/proc/interrupts`), сжатие
`zstd` (многопоточно и в один поток — CPU и память), микротест Python (интерпретатор),
`fio` 4K QD32 и последовательное чтение (по флагу), частоту и EPP CPU, температуру.

Порядок честного сравнения:

1. Одинаковые условия: питание от сети, ноутбук остыл, крышка открыта, Wi-Fi подключён,
   браузер закрыт, 3 прогона — берём медиану.
2. CachyOS — с live-флешки (KDE) или установленный на второй накопитель. Учтите: live
   работает из RAM, поэтому время загрузки и диск у него несравнимы — сравнивайте CPU,
   RAM и пробуждения.
3. Браузер — вручную: Speedometer 3 (`browserbench.org`) в обоих, у нас — в
   **доверенном** профиле (`Super+B`).
4. Чтобы увидеть цену конкретной меры — одна загрузка без неё
   (`VH_EXTRA_CMDLINE="init_on_free=0"` и пересборка UKI, затем вернуть) — глава 11.

## 6. Железо этого ноутбука: что реально даёт скорость

Для MSI GF63 Thin (i5-10500H, UHD 630, один вентилятор) три вещи важнее любых sysctl:

1. **Два модуля памяти (двухканальный режим).** С завода часто стоит один модуль
   8 ГБ. Встроенная графика UHD 630 берёт память из RAM: в двухканальном режиме её
   пропускная способность вдвое выше — плавнее рабочий стол, видео и WebRender в
   браузере, быстрее сжатие zram. Проверка: `00-probe.sh` (раздел «Память») или
   `dmidecode -t memory` [пакет `dmidecode`].
2. **Охлаждение.** Тонкий корпус с одним вентилятором упирается в температуру
   раньше, чем в лимит мощности: чистка радиатора и замена термопасты дают больше,
   чем любая программная настройка. Смотрите `turbostat` под `zstd -T0`: частота и
   причина ограничения.
3. **dGPU обесточена** (`VH_GPU=igpu`, глава 04): GTX 1650 в простое без драйвера
   грела бы общий радиатор и отнимала у CPU тепловой запас.

Драйвер `msi-ec` (режимы вентилятора и «Shift» мощности) в ядре 6.18 модель MS-16R5 не
поддерживает — в его списке только GF63 Thin 11-го поколения (`16R6…`). `00-probe.sh`
проверит это на вашей прошивке EC.
