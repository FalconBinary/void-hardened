# 01. Диск: разметка, LUKS2, XFS

> Модуль 1 промпта. Скрипт: `install/10-install.sh`, разделы «разметка», «LUKS2»,
> «файловые системы». Всё ниже выполняется **[LIVE]** от root.

## 1. Схема

```
/dev/nvme0n1                       GPT
├─ nvme0n1p1   1 GiB   ESP, FAT32   /boot/efi (монтируется только на время обновлений)
│    EFI/BOOT/BOOTX64.EFI          Limine (подписан, с вписанным хэшем конфига)
│    EFI/BOOT/limine.conf          меню: текущая и предыдущая UKI с хэшами BLAKE2B
│    EFI/void/linux-*.efi          UKI: ядро + initramfs + cmdline + микрокод (подписаны)
└─ nvme0n1p2   всё остальное   LUKS2 (aes-xts-plain64, Argon2id)
     └─ /dev/mapper/cryptroot      XFS → /
```

Чего здесь нет и почему:
- **Нет `/boot` на открытом разделе.** Ядро и initramfs лежат внутри подписанной UKI на
  ESP. Подмена любого байта ломает подпись — Secure Boot не загрузит такой файл.
- **Нет swap-раздела.** Swap на диске — это содержимое RAM (в том числе ключи и
  расшифрованные данные) на диске. Вместо него — сжатый swap в RAM (zram,
  [11](11-performance.md)). Гибернации нет: она пишет RAM на диск, а lockdown её и так
  запрещает.
- **Нет LVM.** Один том — меньше слоёв, `rd.lvm=0` в cmdline.

## 2. GPT и разделы

**GPT** (GUID Partition Table) — стандарт разметки UEFI. В отличие от MBR хранит копию
таблицы в конце диска, контрольные суммы и типы разделов в виде GUID.

- **ESP** (EFI System Partition) — раздел с типом `C12A7328-F81F-11D2-BA4B-00A0C93EC93B`,
  FAT32. Прошивка умеет читать только FAT, поэтому загрузчик лежит здесь. Размер
  1 GiB — с запасом: UKI весит 60–100 МБ, их две, плюс Limine.
- **Раздел LUKS** — тип `CA7D7CCB-63ED-4C53-861C-1742536059CC` («Linux LUKS»). Тип
  ни на что не влияет при загрузке (корень указан по UUID), но инструменты
  (`lsblk`, `blkid`) показывают назначение раздела.

Руками:

```sh
lsblk -d -o NAME,SIZE,MODEL           # убедитесь, что это нужный диск
wipefs -af /dev/nvme0n1               # стереть сигнатуры старых таблиц и ФС
blkdiscard -f /dev/nvme0n1            # только при TRIM=yes: «все блоки свободны»
sfdisk /dev/nvme0n1 <<'EOF'
label: gpt
size=1G, type=C12A7328-F81F-11D2-BA4B-00A0C93EC93B, name="ESP"
type=CA7D7CCB-63ED-4C53-861C-1742536059CC, name="cryptroot"
EOF
lsblk /dev/nvme0n1
```

> `blkdiscard` сообщает SSD, что все блоки свободны: старые данные больше не читаются
> через интерфейс диска. Это **не** гарантированное стирание — физически данные могут
> остаться в ячейках до сборки мусора. Для надёжного стирания ранее использованного
> диска — криптостирание (раздел 7).

## 3. LUKS2 изнутри

**dm-crypt** — модуль ядра, который шифрует блочное устройство «на лету»: приложение
пишет открытый текст в `/dev/mapper/cryptroot`, на диск уходит шифртекст.
**LUKS2** — формат заголовка, который хранит, *как* открыть том.

Ключевая идея: **данные шифруются ключом тома (volume key)** — 512 случайных бит,
созданных при `luksFormat`. Ваш пароль этот ключ не шифрует данные напрямую — он
открывает **keyslot**: из пароля функцией Argon2id выводится ключ, которым зашифрован
ключ тома в слоте. Отсюда следствия:

- смена пароля (`luksChangeKey`) не перешифровывает диск — меняется только слот;
- **резервная копия заголовка открывает том старым паролем** (раздел 6);
- если ключ тома утёк (дамп RAM, старый заголовок со слабым паролем), смена пароля
  не поможет — нужен `cryptsetup reencrypt` с новым ключом тома.

Заголовок LUKS2 — бинарная часть + JSON-метаданные (`cryptsetup luksDump` их
показывает), записан дважды (в начале раздела) для живучести.

### Шифр: aes-xts-plain64, 512 бит, сектор 4096

- **AES-XTS** — режим для дисков: каждый сектор шифруется с «твиком» = номер сектора,
  поэтому одинаковые данные в разных секторах дают разный шифртекст.
  `plain64` — 64-битный номер сектора.
- **512 бит** у XTS — это два ключа AES-256 (один шифрует данные, второй — твик).
  Итоговая стойкость — AES-256.
- **Сектор 4096 байт** вместо 512: в 8 раз меньше операций шифрования на тот же объём,
  совпадает со страницей памяти и с физическим блоком NVMe. XFS форматируется с
  тем же размером сектора.
- **XTS не аутентифицирован.** Он не обнаруживает подмену шифртекста. Атакующий,
  у которого есть два образа диска (сделанные в разное время), может вернуть
  отдельный сектор к старому шифртексту — это расшифруется в старую версию данных.
  Обнаружить это можно только офлайн-сверкой ([10](10-audit.md)).
  Аутентифицированное шифрование (`--integrity`, dm-integrity) закрывает это, но стоит
  ~30–50 % скорости записи и места под метаданные — в таблицу мер с ценой.

### Argon2id и почему энтропия пароля важнее параметров

**Argon2id** — функция вывода ключа (KDF), требующая много памяти: каждая попытка
подобрать пароль стоит не только времени CPU, но и гигабайта RAM, что резко
удорожает перебор на GPU и специализированных чипах.

Параметры установщика: `--pbkdf-memory 1048576` (1 ГиБ), `--pbkdf-parallel 4`,
`--iter-time 3000` (cryptsetup подбирает число итераций так, чтобы на *этом* CPU
одна проверка занимала 3 с). Поэтому форматировать нужно на целевом ноутбуке.

Но параметры Argon2id дают выигрыш **константой**, а энтропия пароля —
**экспоненту**:

| Пароль | Энтропия | Попыток в среднем | При 1 попытке/с на ядро и 10⁶ ядер |
|---|---|---|---|
| 8 случайных строчных букв | ~38 бит | 1,4·10¹¹ | ~2 суток |
| 4 слова diceware | ~52 бита | 2,3·10¹⁵ | ~70 лет |
| **7 слов diceware** | **~90 бит** | 6,4·10²⁶ | ~2·10¹³ лет |

Diceware: слово из списка в 7776 слов (5 бросков кубика), каждое слово даёт
log₂(7776) ≈ 12,9 бита. Бросайте настоящие кости или используйте `secrets` в
Python на доверенной машине и [список EFF](https://www.eff.org/dice).

> Удвоение времени Argon2id — это +1 бит. Одно лишнее слово diceware — +12,9 бита.
> Поэтому снижать Argon2id «ради быстрой загрузки» запрещено ([11](11-performance.md)),
> но и надеяться только на него нельзя.

Пароли **разные**: LUKS, админ, пользователь (и, если включите, tpm2-totp). Пароль LUKS
вводится только в initramfs — никогда в работающей системе, где его мог бы увидеть
кейлоггер или поддельное окно.

### Флаги производительности

`--perf-no_read_workqueue --perf-no_write_workqueue --persistent`: по умолчанию
dm-crypt передаёт шифрование в очереди потоков ядра (kcryptd) — это помогает
медленным дискам, но добавляет задержку. Для NVMe и AES-NI выгоднее шифровать
сразу в контексте запроса. `--persistent` записывает флаги в заголовок, и initramfs
применяет их сам. Замер: `fio` до и после ([11](11-performance.md)).

Руками:

```sh
cryptsetup luksFormat --type luks2 --cipher aes-xts-plain64 --key-size 512 --hash sha512 \
  --pbkdf argon2id --pbkdf-memory 1048576 --pbkdf-parallel 4 --iter-time 3000 \
  --sector-size 4096 --label cryptroot /dev/nvme0n1p2
cryptsetup open --perf-no_read_workqueue --perf-no_write_workqueue --persistent \
  --allow-discards /dev/nvme0n1p2 cryptroot        # --allow-discards — только при TRIM=yes
cryptsetup luksDump /dev/nvme0n1p2                  # один keyslot, argon2id, sector 4096, flags
cryptsetup status cryptroot                         # discards, no_read_workqueue…
```

## 4. TRIM: решение

TRIM сообщает SSD, какие блоки свободны: запись быстрее, износ ниже. Цена — по
образу зашифрованного диска видно, *какие* блоки заняты (размер и расположение
данных, но не содержимое).

- **`VH_TRIM=yes` (по умолчанию):** `--allow-discards` для тома и раз в неделю
  `fstrim` сервисом `vh-fstrim` (runit, без cron). Не опция `discard` в fstab: она
  отправляет TRIM на каждом удалении и добавляет задержку.
- **`VH_TRIM=no`:** для тех, у кого в модели угроз есть анализ образа диска.

## 5. XFS

```sh
mkfs.vfat -F 32 -n ESP /dev/nvme0n1p1
mkfs.xfs -f -L voidroot -s size=4096 /dev/mapper/cryptroot
mount -o noatime,logbsize=256k /dev/mapper/cryptroot /mnt
mkdir -p /mnt/boot/efi
mount -o nosuid,nodev,noexec,fmask=0177,dmask=0077 /dev/nvme0n1p1 /mnt/boot/efi
```

- `-s size=4096` — сектор ФС не меньше сектора LUKS (иначе XFS писал бы по 512 байт
  внутри 4K-секторов шифрования — лишние циклы чтения-изменения-записи).
- `noatime` — не записывать время доступа при каждом чтении файла (меньше записи,
  быстрее).
- `logbsize=256k` — буфер журнала 256 КиБ вместо 32: меньше операций записи журнала
  при работе с метаданными (распаковка, компиляция, браузерный кэш). Этот параметр не
  меняется при перемонтировании, поэтому для корня он задан в командной строке ядра
  (`rootflags=`), а не в fstab.
- ESP — с `noexec,nosuid,nodev` и правами только для root (`fmask=0177,dmask=0077`):
  ничего не исполняется с ESP в работающей системе, и обычный пользователь не читает
  UKI. В fstab ESP — `noauto`: монтируется только хуками ядра на время обновления
  ([09](09-updates.md)).

## 6. Резервная копия заголовка

Повреждение первых мегабайт раздела (ошибка разметки, сбой) = потеря всего тома.
Копия заголовка это лечит, но она же — **второй способ открыть том**:

```sh
cryptsetup luksHeaderBackup /dev/nvme0n1p2 --header-backup-file /media/флешка/luks-header.img
```

Политика:
- копию храните на **зашифрованном** внешнем носителе;
- копия открывает том паролем, который действовал **в момент копирования** — при смене
  пароля уничтожайте все старые копии и делайте новую;
- при подозрении, что пароль или заголовок скомпрометированы, смены пароля мало:
  `cryptsetup reencrypt /dev/nvme0n1p2` создаёт новый ключ тома и перешифровывает
  данные на месте (часы, но без потери данных; сделайте бэкап).

Отделённый заголовок (detached header на отдельной флешке) делает раздел
неотличимым от случайных данных, но требует поддержки в initramfs без systemd
[ПРОВЕРИТЬ: man dracut.cmdline — есть ли параметр заголовка для модуля crypt без
systemd] и флешку при каждой загрузке — в базовый слой не входит.

## 7. Опционально: NVMe в 4K и криптостирание

Если диск уже использовался, надёжнее всего стереть его средствами контроллера:

```sh
xbps-install -Sy nvme-cli
nvme id-ctrl -H /dev/nvme0 | grep -iE 'crypto erase|sanitize|format'
nvme id-ns -H /dev/nvme0n1 | grep 'LBA Format'      # есть ли формат «Data Size: 4096»
nvme format /dev/nvme0n1 --ses=2 --lbaf=1           # ВСЁ СТИРАЕТ: криптостирание + 4K (номер lbaf — из вывода выше)
```

`--ses=2` (криптостирание) уничтожает внутренний ключ шифрования контроллера —
старые данные становятся нечитаемыми мгновенно. `--lbaf` с 4096 убирает эмуляцию
512-байтных секторов. Не все контроллеры поддерживают оба режима — смотрите вывод
`id-ctrl`.

## Проверка

```sh
lsblk -f /dev/nvme0n1                   # vfat ESP, crypto_LUKS, внутри xfs
cryptsetup luksDump /dev/nvme0n1p2 | grep -E 'Keyslots|PBKDF|sector|Flags|cipher'
xfs_info / | grep -E 'sectsz|bsize'     # после загрузки: sectsz=4096
findmnt / -o OPTIONS                    # noatime, logbsize=256k
```
