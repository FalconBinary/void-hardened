# 07. Сеть: скорость подключения и пропускная способность

> Модуль 7 промпта. Те же файлы, что в [06](06-network.md); здесь — строки, помеченные
> «(P)» и настройки скорости. Ни одно ускорение не отменяет мер главы 06.

Цели: сеть готова к моменту входа; подключение к известной сети — доли секунды–пара
секунд после включения радио; переключение кабель ↔ Wi-Fi без обрыва; поиск новых
сетей — быстро.

## 1. Холодный старт

- **Регуляторный домен с первой секунды** (`cfg80211.ieee80211_regdom=SI` в cmdline +
  пакет `wireless-regdb`). В «мировом» домене 00 часть каналов 5 ГГц только пассивные —
  точка находится, лишь когда пришлёт маяк. AX201 управляет доменом сам (LAR): до
  первой услышанной точки прошивка может держать мировой домен — `iw reg get`
  покажет `phy#0 (self-managed)` [ПРОВЕРИТЬ на железе].
- **iwd не пересоздаёт интерфейс** (`DefaultInterface=iwlwifi`) — сотни миллисекунд.
- **Стадия 2 runit параллельна**: dbus, iwd, unbound, chronyd стартуют одновременно.
  iwd ждёт шину через `sv -w 5 start dbus` в своём `conf`, а не падает с перезапуском
  через секунду.
- **`/var/lib/iwd` на диске**: iwd хранит частоты, на которых видел известные сети, и
  заранее вычисленные PSK (WPA2) и SAE-PT (WPA3 с H2E). Повторное подключение — без
  полного сканирования и без PBKDF2/SAE-вычислений.
- **IPv6 выключен** — нет ожидания RA и DAD.

## 2. Поиск сетей и подключение

| Настройка | Значение | Эффект | Цена |
|---|---|---|---|
| `[Scan] InitialPeriodicScanInterval` | 3 (по умолч. 10) | без подключения первое пересканирование через 3 с | батарея, эфир |
| `[Scan] MaximumPeriodicScanInterval` | 30 (по умолч. 300) | новая сеть находится максимум за 30 с | батарея, эфир |
| `[Rank] BandModifier5GHz` | 1.5 | при близком качестве — 5 ГГц | — |
| `[Blacklist] InitialTimeout/MaximumTimeout` | 10 / 300 с | точка после единичного сбоя исключается на 10 с (при повторах — до 5 мин), а не на минуту (умолчание) | — |
| `[DriverQuirks] PowerSaveDisable` | iwlwifi | без энергосбережения Wi-Fi | батарея |
| `RoamThreshold/RoamThreshold5G` | −70 / −76 dBm | переход на лучшую точку mesh до заметной просадки | — |
| `DisableANQP` | true | без запросов Hotspot 2.0 (некоторые драйверы сбоят) | — |

Свои сети — со **статическим адресом** (без DHCP: на ~1 с быстрее и без зависимости от
DHCP-сервера), `/var/lib/iwd/ИмяСети.psk`:

```ini
[IPv4]
Address=192.168.1.50
Netmask=255.255.255.0
Gateway=192.168.1.1
```

Чужие сети — DHCP iwd. dhcpcd для Ethernet — с `noarp` (без проверки конфликта
адреса, ~1 с).

**Энергосбережение Wi-Fi** (в ядре Void по умолчанию включено) даёт задержки до
сотен мс и обрывы на AX201. Выключено дважды: `PowerSaveDisable` в iwd и
`iwlmvm power_scheme=1` (`/etc/modprobe.d/vh-iwlwifi.conf`). Проверка:
`iw dev wlan0 get power_save` → `off`. Откат одной строкой: удалить
`PowerSaveDisable=iwlwifi` из `/etc/iwd/main.conf`.

**Своя точка доступа для скорости:** канал 5 ГГц без DFS (36–48): на каналах DFS в
ETSI сканирование только пассивное, а после перезагрузки точки — минута ожидания
радара (CAC). Ширина 80 МГц (160 МГц в этом диапазоне требует DFS). WMM включён,
band steering, задерживающий ответы на 2,4 ГГц, выключен.

## 3. TCP

`/etc/sysctl.d/40-vh-network.conf`, строки «(P)»:

- **BBR + fq** (`tcp_congestion_control=bbr`, `default_qdisc=fq`): BBR оценивает полосу и
  задержку, а не ждёт потерь, как CUBIC. На Wi-Fi с потерями и буферами в роутерах —
  выше скорость и ниже задержка. fq нужен BBR для темпа отправки.
- `tcp_slow_start_after_idle=0` — после паузы соединение не начинает с малого окна
  (важно для HTTP/2 и SSH).
- `tcp_mtu_probing=1` — находит рабочий MTU, если ICMP «фрагментация нужна» где-то
  отбрасывают (частая беда за VPN).
- `tcp_notsent_lowat=131072` — меньше неотправленных данных в буфере сокета →
  ниже задержка интерактивных потоков.
- `rmem_max/wmem_max = 7.5 МБ` — большие буферы для QUIC/HTTP3 (рекомендация
  quic-go/Chromium); программа получает их, только если сама просит.
- `tcp_fastopen=0` остаётся (глава 06): выигрыш одного RTT не стоит идентификатора для
  трекинга, а браузеры TFO почти не используют.
- `ignore_routes_with_linkdown=1` — маршрут через упавший линк сразу не используется:
  выдернули кабель → трафик сразу идёт через Wi-Fi.

## 4. DNS

- Апстримы по IP, без «бутстрап-DNS».
- `prefetch: yes` — популярные записи обновляются до истечения TTL: кэш всегда тёплый.
- `serve-expired` + `serve-expired-client-timeout: 1800` — если апстрим не ответил за
  1,8 с, отдаётся последняя известная запись (RFC 8767).
- `tcp-reuse-timeout`, `max-reuse-tcp-queries` — TLS-соединения к апстримам
  переиспользуются: нет рукопожатия TLS на каждый запрос.
- `fast-server-permil: 900`, `fast-server-num: 2` — 90 % запросов — двум самым быстрым
  апстримам.
- `edns-buffer-size: 1232` — без фрагментации UDP; `aggressive-nsec` — отрицательные
  ответы из кэша DNSSEC.
- Кэш **не** сохраняется на диск (дамп требует remote-control, а файл — история
  посещённых доменов).

## 5. Ethernet RTL8111

EEE (Energy Efficient Ethernet) — частая причина обрывов линка у RTL8168. Правило
`99-vh-net.rules`: `ethtool --set-eee eth0 eee off` при появлении интерфейса.
Проверка: `ethtool --show-eee eth0`. Offload оставляем по умолчанию.

## 6. Кабель ↔ Wi-Fi

Оба интерфейса настроены одновременно, демона-переключателя нет:
- метрика маршрута Ethernet (dhcpcd `metric 100`) меньше, чем у Wi-Fi (iwd
  `RoutePriorityOffset=300`) — при кабеле трафик идёт по нему;
- выдернули кабель — линк падает, `ignore_routes_with_linkdown` убирает маршрут из
  выбора, трафик идёт через уже подключённый Wi-Fi. TCP-соединения с адресом
  Ethernet при этом рвутся (у них другой адрес источника) — сохраняются только
  соединения через VPN.

## 7. Замеры

```sh
# от пользователя (ping — через ICMP-сокет группы netdiag)
ping -c 50 -i 0.2 192.168.1.1                 # задержка и джиттер до шлюза
tracepath -n 1.1.1.1                          # PMTU и путь
time getent hosts example.org                 # холодный и тёплый кэш DNS (повторить)
# подключение после включения радио (от админа):
doas rfkill block wlan; doas rfkill unblock wlan; time sh -c 'until iwctl station wlan0 show | grep -q "State.*connected"; do sleep 0.1; done'
# пропускная способность: iperf3 (xbps-install iperf3) к серверу в LAN
iperf3 -c 192.168.1.10 -t 20 ; iperf3 -c 192.168.1.10 -t 20 -R
```

Сравнивайте «от сети» и «от батареи», с `PowerSaveDisable` и без — так видна цена
каждой настройки в миллисекундах и процентах батареи.

## Запрещённые сетевые «ускорения»

| «Ускорение» | Выигрыш | Что открывает |
|---|---|---|
| WPA2 или WPA2/WPA3 на своей точке | совместимость старых устройств | офлайн-перебор пароля, откат |
| `ManagementFrameProtection=0` | старые точки | deauth-атаки |
| Отказ от случайного MAC | доли секунды при подключении | трекинг между сетями |
| DNS из DHCP / DoH браузера вместо unbound | один хоп | подмена DNS сетью; обход DNSSEC и файрвола |
| DNS к апстриму по UDP 53 | −1 RTT TLS на холодном запросе | слежка и подмена в сети |
| Выключить DNSSEC | несколько мс | подмена ответов |
| `tcp_fastopen` | −1 RTT на повторных соединениях | идентификатор для трекинга |
| Сохранение кэша unbound на диск | тёплый кэш после загрузки | история посещений на диске |

|---|---|---|---|
| (глава про скорость: меры защиты не меняются) | Wi-Fi слушает эфир и при кабеле (режим «скорость») | — (выигрыш: подключение и поиск быстрее, BBR) | Батарея: Wi-Fi без энергосбережения и частое сканирование |
