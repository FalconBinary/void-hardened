# 09. Обновления

> Модуль 9 промпта. Инструменты: `doas vh-update`, хуки `/etc/kernel.d/*/…-vh-*`,
> `vh-limine-update`, `vh-suid-strip`.

## 1. Одной командой

```sh
doas vh-update
```

1. `xbps-install -S` и список обновлений — подтверждение; если в репозитории Void вышел
   xbps новее основы thor — предупреждение «пересоберите thor» (раздел 7);
2. сначала `thor` из локального репозитория (если вы его пересобрали), затем всё
   остальное через `thor update`: пакеты качаются параллельно, политика thor проверяет
   каждый пакет при распаковке и отменяет обновление, если оно притянуло пакет из
   чёрного списка ([18](18-thor.md));
3. если обновилось ядро — его хуки сами пересобирают UKI, подписывают, обновляют
   Limine (раздел 2);
4. если обновились **микрокод, прошивки, dracut, systemd-stub, cryptsetup, limine, sbctl,
   eudev или kmod**, а ядро — нет, UKI пересобирается явно (`xbps-reconfigure -f linux6.18`):
   их пакеты хуков ядра не запускают, и без пересборки новый микрокод не попал бы в систему;
5. снова снимаются вернувшиеся SUID и capabilities (вторая линия: thor снимает их уже
   при распаковке);
6. при обновлении `ca-certificates` — свежий набор корневых сертификатов для unbound;
7. список старых ядер (`vkpurge list`; убрать — `doas vh-deep-clean`, глава 12) и
   процессов со старыми библиотеками (их надо перезапустить или перезагрузиться).

`vh-update` и `vh-pkg` работают с `umask 022`. У админа umask 077, и `doas` его не меняет,
поэтому `doas xbps-install` напрямую оставил бы общие кэши триггеров (база MIME, иконки,
загрузчики gdk-pixbuf, схемы glib) читаемыми только для root. Тогда GTK не загрузит
SVG-иконки и Firefox упадёт на старте. `vh-audit` это проверяет; починка —
`doas sh -c 'umask 022; xbps-reconfigure -f shared-mime-info gdk-pixbuf glib'`.

Частота: ядро и браузер — сразу при выходе исправлений безопасности; остальное —
раз в неделю.

С параноидальными модулями `vh-update` делает больше ([13](13-optional.md)):

- **strict-net** — сначала открывает root доступ к зеркалам на 30 минут (`vh-net xbps`);
- **sb-offline-keys** — если обновляется ядро или то, из чего собирается UKI: пакеты
  скачиваются в кэш (`thor fetch -u`, параллельно) с сетью, затем «вставьте носитель», `vh-keys
  mount` **выключает сеть**, установка из кэша и подпись (с проверкой входных данных UKI
  `vh-uki-verify`), `vh-keys umount` возвращает сеть. Окно, когда ключ db доступен, —
  минуты и без сети;
- **tpm2-totp** — напоминает: при следующей загрузке код один раз не совпадёт, сверьте
  версию ядра и перезапечатайте (`RESEAL`).

Лучшее время для обновления ядра — сразу после загрузки, входом админа на tty2 **до**
первого сеанса пользователя: с момента загрузки не выполнялось недоверенного кода.

## 2. Что происходит при обновлении ядра

```
xbps-install -u linux6.18
 └─ /etc/kernel.d/post-install/ (по алфавиту)
     ├─ 05-vh-esp            смонтировать ESP (fstab: noauto); не вышло — ошибка
     ├─ 20-initramfs          dracut-uefi: UKI → /boot/efi/EFI/void/linux-<ver>.efi
     ├─ 90-vh-uki             vh-limine-update --new <ver>:
     │                          оставить 2 UKI (+ работающую), подписать (sbctl sign),
     │                          limine.conf с BLAKE2B, enroll-config, подписать BOOTX64.EFI
     └─ 99-vh-esp            отмонтировать ESP, если монтировал хук
```

Если хук упал — xbps сообщит об ошибке настройки пакета. Загрузится старое ядро (его
UKI и запись в limine.conf на месте): `vh-limine-update` сначала подписывает и только
потом удаляет устаревшие UKI, а при включённом Secure Boot без ключа db отказывается
работать, вместо того чтобы оставить неподписанную UKI. Исправьте причину и повторите:
`doas xbps-reconfigure -f linux6.18`.

Пакеты ядер в Void помечены `preserve`: файлы старой версии (модули в
`/usr/lib/modules/<старая версия>`) не удаляются при обновлении — поэтому
«предыдущее ядро» в меню Limine загружается вместе со своими модулями. Удалять
старые — `doas vkpurge rm <версия>` (его хук post-remove уберёт UKI и запись Limine)
или все сразу — `doas vh-deep-clean --only kernels` (глава 12, раздел 11).

## 3. Откат

- В меню Limine (1 с при загрузке) — «предыдущее ядро».
- На ESP только **текущая и одна предыдущая** UKI. Удаление старых не отзывает их
  подпись: атакующий, сохранивший старую подписанную UKI, может подложить её
  обратно. Но Limine сверяет BLAKE2B файла с хэшем в конфиге, а конфиг — с хэшем
  внутри подписанного BOOTX64.EFI. Подложить старую UKI можно только вместе со
  старыми limine.conf и BOOTX64.EFI — их подпись тоже ваша. Полностью откат ловит
  tpm2-totp (PCR 4 меняется, [13](13-optional.md)). Отозвать всё старое разом —
  `sbctl rotate-keys` (новые ключи, переподпись).

## 4. Атака заморозки

Подпись индекса xbps не имеет срока годности: зеркало или MITM могут отдавать
старый индекс без новых исправлений. Перед обновлением ядра и браузера сверьте
версию по второму независимому каналу:

```sh
xbps-query -R -p pkgver linux6.18 firefox                                   # что видит xbps
xbps-query -i -R --repository=https://repo-fi.voidlinux.org/current -p pkgver linux6.18   # другое зеркало (-i: только оно)
```

Третий канал — шаблон пакета на GitHub (`srcpkgs/linux6.18/template` в
void-linux/void-packages) и последний 6.18.y на kernel.org — в браузере. Отстаёт —
не обновляйтесь с этого зеркала.

## 5. Обновление BIOS

1. Выключите Secure Boot (пароль BIOS), обновите прошивку.
2. После обновления fTPM может быть очищен, а Option ROM поменяться:
   ключи заново — `20-firstboot.sh` (Setup Mode → enroll), tpm2-totp — заново.
3. Проверьте, что настройки главы 00 не сброшены (VT-x, UEFI Shell, пароль).

## 6. Смена удостоверяющего центра у DoT- или NTS-провайдера

unbound и chrony проверяют сертификаты по системному набору корневых сертификатов
(`/etc/unbound/ca-bundle.pem` — его копия внутри chroot unbound). Он обновляется с
пакетом `ca-certificates` (`vh-update` копирует сам). Если включён пиннинг
(`optional/dns-pin`), новый УЦ вносится вручную после сверки отпечатка по второму
каналу. Временно отключать проверку сертификатов — запрещено.

## 7. Обновление своих программ (thor, netline, инструменты на Zig)

`vh-update` обновляет пакеты Void через thor ([18](18-thor.md)): пакеты качаются
параллельно, политика thor проверяет каждый обновлённый пакет (SUID, хуки, правила udev,
чёрный список). Свои программы проекта в репозитории Void не обновляются:

- пакетный менеджер thor;
- панель netline (Zig);
- инструменты на Zig: `vh-wlfilter`, `vh-acpid`, `vh-limine-update` и др.

Компилятора в системе нет, поэтому новые версии собираются с live-флешки:

```sh
# [LIVE]
cryptsetup open /dev/nvme0n1p2 cryptroot && mount /dev/mapper/cryptroot /mnt
cd void-hardened && git pull
./install/build-tools.sh /mnt       # инструменты на Zig (docs/17)
./install/build-thor.sh /mnt        # thor, если менялся thor/ или вышел новый xbps (docs/18)
./install/build-netline.sh /mnt     # netline
umount /mnt && cryptsetup close cryptroot
```

После загрузки выполните:

- `doas xbps-install -Su thor`, если пересобран thor;
- `doas xbps-reconfigure -f linux6.18`, если обновился `vh-limine-update`.

`vh-update` сам предупредит, когда в репозитории Void появится xbps новее, чем основа
thor: «пересоберите thor».
