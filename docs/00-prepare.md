# 00. Подготовка: угрозы, железо, прошивка, образ, проба

> Модуль 0 промпта. После этой главы у вас будет: понятная модель угроз, разобранное
> железо, настроенный BIOS, проверенный образ Void на флешке и отчёт `00-probe.sh`
> с решениями для `vh.conf`.

## 1. Модель угроз: от чего защищаемся

Защита без модели угроз — это набор случайных настроек. Модель отвечает на три
вопроса: **что** защищаем, **от кого** и **чего мы не можем**.

**Что защищаем:** данные на диске, пароли и ключи в памяти, сеансы в браузере,
целостность самой системы (чтобы взлом не пережил перезагрузку).

**От кого и как (сокращённо из промпта):**

| Сценарий | Что делает атакующий | Чем закрыто в базовом слое |
|---|---|---|
| Кража выключенного ноутбука | Читает диск | LUKS2 + Argon2id + длинный пароль ([01](01-disk.md)) |
| Кража включённого, экран заблокирован | Холодная загрузка: снимает RAM, ищет ключ LUKS | Частично: `init_on_free`, MOR, нет suspend. Полностью — `optional/deadman` ([13](13-optional.md)) |
| «Злая горничная» (evil maid) | Подменяет загрузчик или ядро, ждёт вашего пароля | Secure Boot со своими ключами, подписанная UKI, Limine с хэшами ([03](03-boot.md)); проверка до ввода пароля — `optional/tpm2-totp` |
| BadUSB | Флешка притворяется клавиатурой | В базовом слое — только запрет редких модулей; полная защита — `optional/usb-auth` |
| Враждебный Wi-Fi | Поддельная точка, MITM, подмена DNS | WPA3/PMF, случайный MAC, DNSSEC + DoT, NTS, файрвол ([06](06-network.md)) |
| RCE в браузере | Код атакующего в процессе браузера | Отдельный пользователь, bwrap без user namespace, фильтр Wayland, AppArmor ([08](08-desktop.md)) |
| Эскалация до root через ядро | Эксплойт ядра из песочницы | Lockdown, запрет io_uring/BPF/userfaultfd/редких протоколов, `modules_disabled` ([05](05-system.md)) |
| Закрепление в загрузке | Руткит переподписывает UKI | Ключ db на диске — остаточный риск базового слоя; закрывает `optional/sb-offline-keys` |

**Вне модели** (называем честно): Intel ME и fTPM внутри него, импланты в прошивке,
аппаратные кейлоггеры, компрометация самих разработчиков Void или Mozilla.

> **Почему защита слоями.** Каждая мера закрывает свой класс атак. Если одна не
> сработает (ошибка в профиле AppArmor, 0-day в ядре), атакующему нужно пройти
> следующую. Поэтому браузер одновременно работает от другого пользователя, в
> отдельных namespace, без привилегированных протоколов Wayland и под профилем
> AppArmor — ни одна из этих мер в одиночку не достаточна.

## 2. Железо: что есть и что из этого следует

Конфигурация из промпта (уточнит проба, раздел 7):

### CPU: Intel Core i5-10500H (Comet Lake-H)

- 6 ядер / 12 потоков, 14 нм, микроархитектура — потомок Skylake. Турбо до 4,5 ГГц,
  TDP 45 Вт: в тонком корпусе частота упирается в температуру — поэтому отключённая
  dGPU даёт CPU больше турбо ([04](04-gpu.md)).
- **AES-NI есть** → шифрование диска (aes-xts) стоит единицы процентов: CPU шифрует
  гигабайты в секунду на ядро. Замер: `cryptsetup benchmark`.
- **HWP (Speed Shift) есть** → частотой управляет сам процессор, ОС задаёт только
  предпочтение EPP. Демоны вроде tlp и auto-cpufreq не нужны ([11](11-performance.md)).
- **Intel CET нет** (появился в Tiger Lake): аппаратные теневой стек и IBT не работают —
  на них не опираемся.
- **TME нет** (Total Memory Encryption): RAM не шифруется аппаратно. Ключ LUKS и
  открытый текст лежат в DRAM как есть → защита от холодной загрузки только
  программная.
- **Уязвимости класса Spectre/MDS.** Ожидаемо: Spectre v1/v2 (смягчение — eIBRS),
  GDS/Downfall (микрокод замедляет AVX-gather), MMIO Stale Data, ITS. Точный список —
  `/sys/devices/system/cpu/vulnerabilities/*` [ПРОВЕРИТЬ пробой]. Отключать смягчения
  ради скорости — **запрещённое ускорение** ([11](11-performance.md)).
- **VT-x / VT-d.** VT-d (IOMMU) нужен — он защищает от DMA-атак устройств. VT-x нужен
  только для виртуальных машин: если KVM не используется, выключите его в BIOS —
  эксплойт ядра тогда не сможет поставить «тонкий гипервизор» под ОС.

### Графика: Intel UHD (iGPU) + NVIDIA GTX 1650 Mobile (TU117)

- UHD Graphics — поколение Gen9.5, драйвер `i915`. Аппаратное декодирование
  (VA-API, драйвер `iHD` из `intel-media-driver`): H.264, HEVC, VP9. **AV1 — нет**
  (появилось в Gen12) → видео AV1 декодирует CPU. Поэтому в доверенном профиле
  браузера AV1 выключен, и YouTube отдаёт VP9, который декодирует GPU.
- GTX 1650 — Turing. Проприетарный драйвер `nvidia` в Void собирается через DKMS на
  целевой машине (нужны gcc и заголовки), а неподписанный модуль lockdown не
  загрузит — поэтому он исключён ([04](04-gpu.md)). Варианты: dGPU обесточена
  (по умолчанию) или nouveau/NVK.
- **Важно для ноутбуков с GTX 1650:** порт HDMI часто разведён на NVIDIA. Тогда при
  обесточенной dGPU внешний монитор не работает. Проба (раздел 7) это покажет.

### Сеть

- **Wi-Fi 6 + Bluetooth 5: Intel AX201** в исполнении CNVi `[8086:06f0]`: радиочасть
  на модуле, MAC-часть — в чипсете (PCH). Драйвер `iwlwifi` + `iwlmvm`, прошивка из
  `linux-firmware-intel`. Bluetooth этого модуля — **внутреннее USB-устройство**
  `8087:0026`.
- **Ethernet: Realtek RTL8111/8168** `[10ec:8168]`, драйвер `r8169`, прошивка
  `rtl_nic/*` из `linux-firmware-network`. У RTL8168 известны обрывы из-за EEE
  (энергосбережение Ethernet) — выключаем ([07](07-network-speed.md)).

### TPM, сторож, клавиатура

- **TPM 2.0** — вероятнее всего fTPM Intel PTT, работающий внутри ME (драйвер
  `tpm_crb`). Плюс: шину TPM нельзя прослушать. Минус: доверие к TPM = доверие к ME.
- **Аппаратный сторож iTCO** в чипсете (`iTCO_wdt`): может перезагрузить зависшую
  машину. Прошивка иногда блокирует бит NO_REBOOT — тогда сторож недоступен.
- **Встроенная клавиатура** — обычно PS/2-контроллер `i8042`, на части игровых
  ноутбуков — внутренний USB (контроллер ITE). От этого зависят правила
  USB-авторизации ([13](13-optional.md)).

## 3. Настройки прошивки (BIOS/UEFI)

Названия пунктов у производителей разные (Insyde H2O у Acer/HP/Lenovo, AMI Aptio у
ASUS/MSI). Если пункта нет — это остаточный риск: запишите его.

**Сразу, до установки:**

| Настройка | Значение | Зачем |
|---|---|---|
| Boot Mode / CSM | UEFI, CSM выключен | Secure Boot и UKI работают только в UEFI |
| Secure Boot | **выключен на время установки** | live-образ Void не подписан |
| Intel PTT / fTPM | включён | TPM для tpm2-totp и журнала измерений |
| VT-d / Kernel DMA Protection | включён | IOMMU: защита от DMA-атак |
| VT-x | выключен, если не нужен KVM | нет «тонкого гипервизора» под ОС |
| Fast Boot | выключен | иначе прошивка может не инициализировать USB-клавиатуру для пароля, а PCR будут нестабильны |
| Wake on LAN, PXE / Network Boot | выключены | лишняя поверхность |
| Камера, картридер, Thunderbolt, AMT | выключить то, чем не пользуетесь | меньше драйверов и устройств с DMA |
| Absolute / Computrace (persistence) | выключить навсегда | агент в прошивке, который ставится в ОС |
| Turbo Boost, C-states | включены | производительность и батарея (защиту не ослабляют) |
| Графика | гибридная (MSHybrid/Optimus), не «только dGPU» | иначе iGPU отключена и dGPU не обесточить |

**После установки (этап 2, [03](03-boot.md)):**

- пароль администратора (supervisor) BIOS — без него Secure Boot выключается одной
  кнопкой; если прошивка позволяет — дата и время меняются только под паролем;
- Secure Boot: сброс в Setup Mode → регистрация своих ключей → включить;
- загрузка с USB/сети, меню выбора загрузки, UEFI Shell — выключить;
- очистка TPM по запросу ОС — только с физическим подтверждением (PPI), если есть пункт;
- защита от отката прошивки (BIOS rollback/downgrade protection), датчик вскрытия
  корпуса — включить, если есть.

**Обновите BIOS до установки.** Уязвимости прошивки (LogoFAIL, PKfail и т. п.) обходят
Secure Boot. Сверьте версию с бюллетенями производителя; если в BIOS можно
загрузить свой логотип — выключите эту функцию.

### MSI GF63 Thin 10SCXR / 10SCSR (MS-16R5) — где что лежит

Ноутбук автора: модель MS-16R5 (i5-10500H, GTX 1650 Max-Q, AX201NGW). Прошивка — AMI
Aptio в оформлении MSI. Названия пунктов зависят от версии BIOS — если пункта нет, это
остаточный риск: запишите его [ПРОВЕРИТЬ на своей версии].

| Что | Где |
|---|---|
| Войти в BIOS / меню загрузки | `Del` / `F11` при включении |
| Расширенные пункты (VT-x, VT-d, PTT) | скрыты. На экране BIOS: **правые Ctrl + Shift, левый Alt, затем F2** — появится вкладка Advanced с полным набором. На части версий — левые Ctrl + Alt, правый Shift + F2 |
| Пароль администратора | Security → Administrator Password |
| Secure Boot | Security → Secure Boot: «Secure Boot Support»; «Secure Boot Mode» → Custom → Key Management → **Delete All Secure Boot Variables** — это и есть Setup Mode для этапа 2 |
| VT-x | Advanced → CPU Configuration → Intel Virtualization Technology |
| VT-d | Advanced → System Agent (SA) Configuration → VT-d |
| TPM (PTT) | Advanced → PCH-FW Configuration (или Trusted Computing) → TPM Device: PTT, Security Device Support: Enabled |
| Fast Boot, UEFI | Boot → Fast Boot: Disabled; Boot mode: UEFI |
| Камера | пункта в BIOS обычно нет; **Fn+F6** отключает её на уровне EC — устройство пропадает с шины USB. В системе она ещё и деавторизуется правилом udev (`VH_CAMERA=no`) |

Особенности модели, важные для этой системы:

- **HDMI.** По спецификации MSI порт HDMI у GF63 Thin выдаёт 4K только при 30 Гц — так
  бывает, когда порт разведён на встроенную графику Intel. Тогда `VH_GPU=igpu` внешний
  монитор не отключает. Проверьте пробой (раздел «Выходы видео»): порт должен
  принадлежать драйверу `i915`, а не `nouveau` [ПРОВЕРИТЬ].
- **Память.** С завода часто один модуль 8 ГБ — UHD 630 тогда работает в одноканальном
  режиме. Второй такой же модуль даёт двухканальный режим: это самый большой прирост
  скорости графики и zram на этом ноутбуке ([15](15-cachyos.md)).
- **Охлаждение.** Один вентилятор на CPU и GPU: частота упирается в температуру.
  Драйвер `msi-ec` (режимы вентилятора и мощности) в ядре 6.18 эту модель не знает —
  проба проверит прошивку EC. Режимы MSI Center остаются только в Windows.
- **Обновление BIOS.** MSI выпускает прошивки для этой модели (`E16R5IMS.*`) с
  программой прошивки под Windows [ПРОВЕРИТЬ на сайте MSI: есть ли вариант для
  встроенного M-Flash или EFI Shell]. Обновите **до** установки: потом понадобится
  выключать Secure Boot и заново вносить хэши Option ROM ([09](09-updates.md)).

## 4. Скачивание и проверка образа

Устанавливаем с официального live-образа Void (glibc, x86_64, «base»):
`https://repo-default.voidlinux.org/live/current/void-live-x86_64-<дата>-base.iso`.

### Почему проверка подписи, а не только контрольной суммы

`sha256sum.txt` лежит на том же сервере, что и образ: кто подменил образ, подменит
и сумму. Поэтому список сумм **подписан** ключом проекта (minisign), а ключ мы
получаем по **другому каналу** — и сверяем по третьему.

```sh
# на любом компьютере с minisign (Linux: пакет minisign, macOS: brew install minisign)
curl -LO https://repo-default.voidlinux.org/live/current/void-live-x86_64-20250202-base.iso
curl -LO https://repo-default.voidlinux.org/live/current/sha256sum.txt
curl -LO https://repo-default.voidlinux.org/live/current/sha256sum.sig
# канал 1: публичный ключ из репозитория пакетов на GitHub
curl -L -o void-release-20250202.pub \
  https://raw.githubusercontent.com/void-linux/void-packages/master/srcpkgs/void-release-keys/files/void-release-20250202.pub
minisign -Vm sha256sum.txt -x sha256sum.sig -p void-release-20250202.pub
sha256sum -c --ignore-missing sha256sum.txt     # на macOS: shasum -a 256 -c
```

Канал 2 — тот же ключ в пакете `void-release-keys` (файл
`/etc/signify/void-release-20250202.pub` на любой системе Void). Строки ключа
должны совпасть символ в символ. На момент написания:

```
untrusted comment: minisign public key 4D56E70F102AF9F9
RWT5+SoQD+dWTeOdNuc4Q/jq2+3+jpql7+JJp4WukkxTdpsZlk2EGuPj
```

> Комментарий ключа «untrusted comment» не подписан и ничего не доказывает. Проверяется
> только вторая строка. Строка «Trusted comment» в выводе minisign — подписанная:
> там сказано, для образов какой даты ключ действует.

### Запись на флешку

Linux: `dd if=void-live-…-base.iso of=/dev/sdX bs=4M status=progress oflag=sync`
(`sdX` — флешка целиком, не раздел; `lsblk` поможет не перепутать с диском).
macOS: `sudo dd if=… of=/dev/rdiskN bs=4m` (номер — из `diskutil list`).
Windows: Rufus в режиме «DD-образ».

## 5. Загрузка live-среды

1. Вставьте флешку, в меню загрузки (обычно F12 / F8 / Esc) выберите её **в режиме UEFI**.
2. В меню GRUB — первый пункт. Если экран чёрный — пункт «graphics disabled».
3. Вход: `root` / `voidlinux` (или `anon` / `voidlinux`).
4. Раскладка уже `us`; кириллица в консоли не нужна.

### Сеть в live-среде

Проще всего — кабель: `dhcpcd` в live-среде поднимет его сам (`ip a` — есть ли адрес
у `eth0`/`enp…`). Wi-Fi в live-среде — через `wpa_supplicant`:

```sh
ip link                                   # имя беспроводного интерфейса, например wlp0s20f3
wpa_passphrase 'ИмяСети' 'пароль' > /tmp/wpa.conf
wpa_supplicant -B -i wlp0s20f3 -c /tmp/wpa.conf
dhcpcd wlp0s20f3
ping -c3 voidlinux.org
```

> Пароль сети в `/tmp/wpa.conf` живёт только в RAM live-среды.

### Получить установщик

```sh
xbps-install -Syu xbps
xbps-install -Sy git
git clone https://github.com/FalconBinary/void-hardened.git
cd void-hardened
```

## 6. Проба железа

```sh
./install/00-probe.sh --install-tools
```

Скрипт ничего не пишет на диски. `--install-tools` ставит в live-среду (в RAM)
`pciutils usbutils tpm2-tools nvme-cli iw efibootmgr dmidecode`. Отчёт — в
`/tmp/vh-probe-<дата>.txt`; в конце — список рекомендаций. Скопируйте отчёт на
флешку или отправьте себе: после перезагрузки /tmp исчезнет.

Что смотреть в отчёте и как это влияет на `vh.conf`:

| Раздел отчёта | Что ищем | Решение |
|---|---|---|
| Выходы видео | `HDMI-A-1 … драйвер=nouveau` | внешний монитор нужен → `VH_GPU="nouveau"` |
| TPM | `TPM2_PT_MANUFACTURER … "INTC"` | fTPM PTT — норма; нет TPM → включить PTT в BIOS |
| TPM: Option ROM | число `EV_EFI_BOOT_SERVICES_DRIVER` | 0 → свои ключи без Microsoft; >0 → `--tpm-eventlog` ([03](03-boot.md)) |
| Прошивка | `MOR: 0/1` | есть MOR → перезагрузка стирает RAM |
| USB: connect_type | внешние порты не `hardwired` | важно для `optional/usb-auth` |
| Устройства ввода | `isa0060` у клавиатуры | i8042 — проще; USB — учесть в правилах USB |
| Накопители | `LBA Format … 4096` | можно перевести NVMe в 4K (опционально, [01](01-disk.md)) |
| Аппаратный сторож | `iTCO_wdt` в lsmod, нет ошибки NO_REBOOT | нужно для `optional/deadman` |

## 7. VM-стенд: проверить всё до ноутбука

Промпт требует прогонять цепочку на стенде: qemu + OVMF с Secure Boot + программный
TPM (swtpm). В репозитории это `tests/vm/vhvm.py`:

```sh
# Linux: пакеты qemu, edk2-ovmf (или ovmf), swtpm, xorriso. macOS: brew install qemu swtpm
python3 tests/vm/vhvm.py install --iso void-live-x86_64-20250202-base.iso --netline
python3 tests/vm/check.py all             # base, enroll, sb, lock, desktop
python3 tests/vm/check.py deadman         # дамп RAM после выключения: без модуля и с ним
python3 tests/vm/check.py totp --repo     # tpm2-totp на swtpm (--repo: свежие файлы в VM)
sh tests/c/build.sh                       # инструменты на C для --repo (через docker)
sh tests/c/run.sh                         # тесты инструментов на C против Python-эталона (docs/17)
```

Стенд поднимает VM с NVMe-диском, пустой прошивкой в Setup Mode и TPM, грузит
live-образ, ставит систему этим же установщиком (пароли тестовые), затем загружает
её через Limine → UKI → ввод пароля LUKS и выполняет команды. Всё общение — через
последовательную консоль (`VH_TEST_SERIAL=yes` включает вход админа на ttyS0 — на
железе не включайте). На Mac с Apple Silicon x86 эмулируется программно: установка
занимает около часа.

## 8. Замеры «до»

Чтобы потом честно сказать, сколько стоит каждая мера, снимите базу (подробно —
[11](11-performance.md)): время загрузки по этапам, `cryptsetup benchmark`, Speedometer 3
в браузере, загрузка CPU при видео 1080p. Проще всего — на текущей системе ноутбука
до переустановки и затем на новой с выключенной мерой (например, без `init_on_free`).

## Итог главы

| Защищает от | Остаточный риск | Цена в скорости | Цена в удобстве |
|---|---|---|---|
| Подмены образа (подпись + два канала), «тонкого гипервизора» (VT-x off), DMA (VT-d), лишнего железа | Прошивка без пароля и защиты от отката; ME/PTT; LogoFAIL на старом BIOS | нет | Пароль BIOS; нет KVM, если VT-x выключен |
